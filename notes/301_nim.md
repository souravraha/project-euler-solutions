# Problem 301: Nim

*Count the positive integers n <= 2^30 for which the three-heap, normal-play Nim position X(n, 2n, 3n) has nim-sum 0 (a losing position for the player to move).*

## The naive approach

Loop over all 10^9 values up to 2^30, compute the nim-sum `n ^ 2*n ^ 3*n`
for each, and count the zeros. Correct, but it is a billion-iteration loop
for a quantity that has a closed form.

## The insight

`X(a, b, c) = 0` means the nim-sum is zero, i.e. `n ^ 2n ^ 3n = 0`.
Because `3n = n + 2n`, this happens **exactly when adding n and 2n
produces no carry**, i.e. when `n & 2n == 0`. Since `2n` is just `n`
shifted left by one bit, `n` and `2n` share a set bit *iff* `n` has two
**adjacent 1-bits**. So the losing positions are exactly the n with no two
adjacent 1-bits in binary.

Counting L-bit binary strings with no adjacent 1-bits is the Fibonacci
number F(L + 2) (the f(1)=2, f(2)=3 recurrence). The range [1, 2^30] is
[0, 2^30 - 1] minus n = 0 and plus 2^30; since 2^30 has a single set bit
(valid) and n = 0 is also valid, those two adjustments cancel and the
answer is exactly F(32).

```
X(n, 2n, 3n) = 0
<=> n ^ 2n = 3n = n + 2n
<=> n & 2n == 0
<=> no two adjacent 1-bits in n
```

Verified against brute force for L = 1..8 (all match).

## Complexity

- Time: `O(log N)` for the Fibonacci recurrence - vs. `O(N)` to enumerate a billion values
- Space: `O(1)`
- Measured: ~1.9 us per call in CPython (timeit, 200k runs)

**Answer:** `2178309`.
